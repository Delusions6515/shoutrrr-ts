# Compatibility

`shoutrrr-ts` currently supports **Generic Webhook, Bark, Discord, Gotify, Google Chat, IFTTT, Join, Mattermost, ntfy, OpsGenie, Pushover, Pushbullet, Rocket.Chat, Slack, Microsoft Teams, and Zulip** URLs (16 of 19 upstream push services). Go Shoutrrr commit `ccf81390b700948f85ce1c79f6de9ee75c68d9e5` is the behavioral authority. The implementation was bootstrapped from the woodpecker snapshot recorded in `THIRD_PARTY_NOTICES.md`. The status of every push service is recorded in `test/compatibility/services.json`; `hangouts` is an alias for Google Chat, not a twentieth service.

Supported Generic forms include `generic://` and `generic+https://` URLs, Generic request options, custom `@Header` values, and `$` JSON fields. Generic defaults to HTTPS. `disabletls=yes` is the explicit HTTP selector; no implicit downgrade occurs. Generic shortcuts normalize query escaping through Go's router conversion (for example, `%20` becomes `+`).

Bark supports `bark://:device-key@host/path?title=...&badge=...` and the upstream query options `scheme`, `sound`, `icon`, `group`, `url`, `category`, and `copy`. Bark defaults to HTTPS and posts JSON to `/push` below the configured path. `scheme=http` permits unencrypted transport, which exposes the device key in the request body. Local tests compare Go-produced request and response outcomes for defaults, options, a non-200 API code, and an HTTP error; they also exercise sender overrides and public error redaction. Live Bark delivery has not been verified.

Discord sends JSON embeds to the fixed HTTPS webhook endpoint and accepts only HTTP 204 as success. The default line mode, configured title/color/username/avatar and thread query, unsplit plain text, and `/raw` JSON-body mode are compared with Go fixtures. When a message spans more than one batch, the pinned Go code reuses its first batch's backing slice; the local parity test preserves the resulting overwritten first item and verifies that later batches are attempted after an earlier failure. Raw mode sends bytes unchanged, even if the input is not valid JSON; callers are responsible for supplying valid Discord payloads. Very large Unicode messages and live Discord delivery remain unverified.

Gotify accepts an application token as the final URL path segment, validates its 15-character format, and posts JSON to `/message` with the token in the outbound query. The default is HTTPS; `disabletls=Yes` selects HTTP. The pinned Go client also disables certificate verification if that HTTP request redirects to HTTPS; Node Fetch does **not** reproduce this insecure redirect behavior. Redirects to hosts with invalid certificates will fail in this package. Gotify tests cover default/options requests, HTTP errors, token validation, and redaction; live delivery has not been verified.

Mattermost and Rocket.Chat post JSON to HTTPS webhook endpoints. Go request fixtures cover default and configured username/channel/icon or override behavior and non-200 responses. Mattermost rejects unknown send-time parameters before posting, including `username` and `channel`; Rocket.Chat accepts those two payload overrides. Their live delivery has not been verified.

Pushover sends a Go-encoded form POST to the upstream fixed endpoint. Its device list and priority affect the submitted fields; priorities outside -2 through 1 are omitted, matching the pinned Go code. Join sends an empty-body POST whose query contains the device IDs, API key, message, and optional title/icon. These keys and the fixed-host outbound URLs are privileged data: never log them. Local requests, status handling, and public redaction are tested; neither service has been verified against a live platform.

Google Chat posts JSON to the configured HTTPS webhook with Go-encoded `key` and `token` query values. The pinned Go revision accepts an omitted token due to a duplicated key check; `hangouts://` is an alias for this same service and does not increase the service count. Local request, HTTP status, transport, and validation behavior is tested; live delivery is unverified.

Pushbullet posts JSON notes to its fixed HTTPS endpoint with the 34-character API token in the `Access-Token` header. Its token is case-sensitive even though it occupies the configuration URL host; the router preserves the original authority for this service. Multi-target sends occur in order and stop on the first failure. Local tests compare Go-captured target order, token casing, success, and failure; live delivery is unverified.

Zulip uses a form POST with Basic authentication to `/api/v1/messages`, preserves per-send stream/topic overrides, and rejects topics above 60 Unicode characters or messages above 10,000 bytes. Node Fetch cannot accept Go's credential-bearing HTTP URL, so the adapter sends the same credentials in the Authorization header without userinfo in the transport URL. This normalization is tested against the Go header and destination; live delivery is unverified.

ntfy sends the message as untyped raw bytes with Go's notification headers, including priority, tags, actions, cache and Firebase controls. Its default protocol is HTTPS; `scheme=http` opts into HTTP. When URL credentials include a password, the Node adapter sends the same Basic authentication header without credential-bearing Fetch URL userinfo. Local HTTP and Go-captured tests check absent Content-Type, option headers, response failures, and credential redaction. Live delivery remains unverified.

IFTTT posts the same JSON values to each configured event in order, stopping on the first rejected response. Its `messagevalue` option selects a value field; the pinned Go `titlevalue` option is accepted but does not populate a value field. Go prints the raw payload to stdout; this package deliberately does **not** reproduce that credential-leaking diagnostic. The Go baseline harness suppresses upstream stdout while recording only synthetic requests. Live IFTTT delivery is unverified.

Microsoft Teams supports the pinned Go `teams://` legacy and tenant-scoped webhook forms and the `teams+https://` webhook shortcut. The four token parts are validated before posting a JSON MessageCard; the `host`, `title`, and `color` options affect the endpoint or card. The local Go fixtures compare the legacy and tenant-scoped destinations, shortcut, card sections, and non-200 failure. The webhook URL and tokens are privileged configuration. Live Teams delivery is unverified.

OpsGenie posts an alert JSON body over HTTPS to the configured host and port, with the API key in the `GenieKey` authorization header. It supports query and per-send alert fields, including entity lists and key/value details; overrides are scoped to one send. The message field uses Go's 130-byte truncation when no title is supplied, and any 2xx response succeeds. Go-captured local cases cover options, rejected HTTP status, and transport failure; live OpsGenie delivery is unverified.

Slack supports legacy and modern incoming-webhook URLs plus `xoxb`/`xoxp` API-token URLs at the pinned Go revision. It posts line attachments to a fixed HTTPS endpoint; API mode uses a Bearer authorization header and requires `ok: true` inside the JSON response, whereas webhook mode checks the response text. Title, icon, bot name, color, and thread settings follow Go's query and persistent send-override behavior. Local fixtures cover both modes, a rejected API response inside HTTP 200, HTTP failure, and transport failure. Tokens and outbound URLs are privileged; live Slack delivery is unverified.

Telegram remains **deferred and unregistered**. The pinned Go client reports success for a synthetic HTTP 200 `sendMessage` response containing `{"ok":false}`, despite the vendor-level rejection. A TypeScript adapter that rejects that response would diverge from Go; one that returns success would hide delivery failure. The recorded Go case is retained for a future explicit compatibility decision. No Telegram delivery is claimed.

Node Fetch may add transport headers that differ from Go's HTTP client. These runtime-generated headers are intentionally excluded from service compatibility assertions. Raw webhook URLs are privileged configuration, not untrusted input: parsing does not prevent SSRF, and applications must not accept destinations from attackers.

## Service promotion gate

A service is public only after URL, request, failure, redaction, Node runtime, and documentation checks pass. Other imported service implementations are not registered or supported. Recorded Go requests for stable services can be rechecked against the pinned Go checkout with `pnpm verify:go-baseline` (set `SHOUTRRR_GO_ROOT` if the checkout is not beside this repository). The pinned Go checkout omits an imported fuzzing module from `go.mod`; the verifier pins it in a temporary modfile without changing upstream. This command is not part of `pnpm check` because clean package consumers do not need Go or an upstream checkout. `pnpm check` validates committed observations and TypeScript behavior; re-run the Go verifier before changing reference fixtures. Local simulation proves agreement with this Go revision, not successful live-provider delivery. Live-platform behavior remains unverified.
